### 1. Provider-profile persistence
**State:** Resolved
**Value:** Resolved as LD-014.
**Investigation:** EV-002 found one combined `sayslate-grammar-config` record in `chrome.storage.local`; EV-010 showed that Argus's Electron-only `safeStorage` cannot be reused by a browser extension.
**Why user input is required:** Source inspection established the available mechanisms but could not choose the accepted credential threat model or whether users should re-enter keys after every session; the user has now resolved that choice.
**Recommendation:** Persist versioned, provider-scoped profiles in `chrome.storage.local`, keep the active profile ID separate, and do not introduce a native credential host. This follows SaySlate's existing storage boundary while preventing one provider save from replacing another.
**Evidence:** EV-002, EV-010, and Dustin Thomason's 2026-09-22 clarification.

### 2. Gemini transport

### 3. Long-running inference ownership
**State:** Resolved
**Value:** Resolved as LD-016.
**Investigation:** EV-017 establishes that current Gemini calls are renderer-owned and bounded at 90 seconds; EV-006 shows the service worker owns asynchronous Whisper routing, not AI inference; EV-011 documents the service-worker fetch-response lifetime risk. The current code therefore does not implement a durable AI-request owner.
**Why user input is required:** Source inspection could not decide the expected product behavior when the initiating surface disappears. Requiring survival would create a new durable/offscreen ownership boundary; the user confirmed that preserving today's renderer-owned behavior is appropriate.
**Recommendation:** Preserve renderer-owned inference for this feature: let closing or navigating away cancel the request while retaining the user's source text and last completed result. This supports slow requests while the surface remains open, matches current behavior, and avoids introducing an unproven service-worker/offscreen lifetime mechanism until real usage demonstrates that detached completion is necessary.
**Evidence:** EV-006, EV-011, EV-017, and Dustin Thomason's 2026-09-22 confirmation of decision 3.
**Depends on:** —

### 4. Custom-origin permissions
**State:** Resolved
**Value:** Resolved as LD-017.
**Investigation:** EV-018 establishes that SaySlate currently has a fixed two-origin allow-list, has no optional-host-permission flow, and deliberately fails verification if another origin appears. EV-012 establishes that the new Tailscale/custom-provider request needs a granted host permission.
**Why user input is required:** Both mechanisms can satisfy the network requirement. The user selected preset providers with editable, saved, testable endpoints; least-privilege optional permission for the exact selected origin is the compatible technical consequence.
**Recommendation:** Declare custom HTTPS access as optional and request only the exact configured origin when the user saves or tests that provider. Retain the existing fixed Gemini permission, avoid broad install-time host access, and fail visibly if the user declines the origin grant.
**Evidence:** EV-012, EV-018, and Dustin Thomason's 2026-09-22 provider/endpoint UX direction.

### 8. Legacy migration after delete or clear

### 9. Models that cannot enforce the schema
**State:** Resolved
**Value:** Resolved as LD-031.
**Investigation:** The origin asks for "JSON schema whenever possible" ([original ticket](./sayslate-ai-provider-tailscale-original-ticket.md), rough MVP), and LD-003 rejects "Unconditional JSON Schema support". LD-025 fails every request whose provider rejects the schema and rejects "free-form unvalidated fallback", but does not mark LD-003 superseded. Today's Gemini path already accepts the model's free text as the result (EV-003, EV-005), and LD-022 unwraps the structured result to that same plain string.
**Why user input is required:** LD-003 and LD-025 point in different directions, and neither records superseding the other. Which models SaySlate must remain usable with is a product choice the code cannot settle.
**Recommendation:** Keep LD-025's schema request and validation, but when the provider rejects the schema itself, retry once without it and accept only a trimmed, non-empty text reply. This keeps "whenever possible" and LD-003 intact and every model usable. The cost is that the fallback path loses the schema's guard against extra commentary around the text — the same exposure today's Gemini path already has.
**Evidence:** Original ticket, rough MVP; LD-003; LD-022; LD-025; EV-003; EV-005; Dustin Thomason's 2026-09-22 answer choosing the retry.
**Depends on:** —
