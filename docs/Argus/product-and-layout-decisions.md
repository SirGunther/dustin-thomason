# Argus Product and Layout Decisions

This is the canonical decision register for visible product behavior and layout. Detailed payload examples and runtime rules remain beside the implementation in `Architecture\DesignDecisions.md` and `Architecture\RuntimeKernelAndPlanes.md`.

Statuses are **Accepted**, **Proposed**, **Open**, or **Superseded**. A later decision must explicitly supersede an earlier one; prior rationale remains part of the record.

## Decision register

| ID | Status | Decision | Reason and consequence |
| --- | --- | --- | --- |
| PD-001 | Accepted | The live primary output is a neutral **Logged Item**. | Extraction should capture useful meaning without making an uncertain category look authoritative or enlarging every row. |
| PD-002 | Accepted | Every logged item exposes the exact transcript source range considered. | A concise item must remain auditable and recoverable in context; persistent contracts use stable segment IDs while the UI displays timestamps. |
| PD-003 | Accepted in principle | Extraction is chunk-driven and off the word-by-word transcription path. | Coherent windows reduce noise, cost, and unstable output. Pause, size, topic, and maximum-latency thresholds still need measurement. |
| PD-004 | Accepted | Classification is a separate optional, lowest-priority suggestion. | A category can use the exact source range plus bounded surrounding context without delaying capture. It enters the AI lane after transcription and extraction, is bound to an item revision, and may not silently mutate logged items. |
| PD-005 | Accepted for POC | Toasts occupy top-center negative space. | Notifications remain visible without covering the newest transcript or logged items at the bottom of either pane. |
| PD-006 | Accepted | Desktop layout uses two equal, independently scrolling panes. | Transcript and extracted meaning can be compared continuously while preserving separate live-follow state. |
| PD-007 | Accepted | Rows are compact horizontal records with selection, time/provenance, editable text, and copy action. | High information density supports long live sessions while keeping all actions associated with one row. |
| PD-008 | Accepted | Stop and Close Session are different operations. | Stop preserves resumable working state; Close is an explicit, irreversible finalization boundary. |
| PD-009 | Accepted | Finalization requires a confirmation modal with record counts. | A destructive lifecycle transition should be deliberate and show what is being finalized. |
| PD-010 | Accepted | Session metadata and storage are disclosed in a side drawer. | Operational detail is available on demand without consuming the primary live workspace. |
| PD-011 | Accepted | Copy behavior is available per row and per selected batch, with one global timestamp preference. | Fast extraction from the session is a primary workflow; a shared preference keeps output predictable. |
| PD-012 | Accepted | Autosave is the normal path; there is no routine Save button. | Live capture should not require manual persistence steps. Save status remains visible. |
| PD-013 | Accepted | Scrolling upward pauses live following only for that pane; Jump to live restores it. | Reading earlier material must not be disrupted, and activity in one pane must not seize the other pane's scroll position. |
| PD-014 | Accepted for POC | Narrow layouts stack the two panes and reduce secondary chrome. | The POC remains inspectable below desktop width without redesigning the core information hierarchy. |
| PD-015 | Accepted | Playback controls are absent. | Playback was explicitly outside the initial interface requirement. |
| PD-016 | Open | Row deletion and recovery semantics. | The current POC supports editing but not deleting. The product must decide soft delete versus permanent removal and preserve transcript/log provenance. |
| PD-017 | Open | Where classification suggestions are reviewed and what acceptance affects. | No badge belongs in the primary list until edit/review, export, filtering, and automation behavior are understood. |
| PD-018 | Accepted for architecture POC | Browser folder actions remain honest simulations until a desktop shell owns OS integration. | HTML alone cannot safely prove the packaged filesystem capability. |
| PD-019 | Accepted; implementation deferred | Focusing a row editor pauses live following for that pane until editing ends or the user explicitly returns to live content. | Incoming rows must not move the control under an active editor. The Phase 7A bug is deferred while Phase 8 proceeds. |
| AD-001 | Accepted and implemented | Domain and control messages use separate explicit, default-deny planes. | Startup, supervision, result collection, and completion remain visible architecture instead of hidden orchestrator behavior. |
| AD-002 | Accepted and implemented | Runtime mechanics have a finite documented authority boundary. | The kernel may host and validate processes/messages but may not invent, interpret, or bypass domain behavior. |
| AD-003 | Accepted and implemented | Components are replaceable only through versioned contracts and compatible declared ports. | A drop-in claim is demonstrated by substituting extractors in the same graph position and rerunning the same tests. |
| AD-004 | Accepted direction; provider boundary implemented | Argus is polyglot and container-capable by architectural intent; Node remains the baseline orchestrator but not a required component language. | Manifests now discriminate Node/native/container and launching goes through a trusted provider boundary, but Node is still the sole active provider. Native and OCI replacement proofs remain pending. |
| AD-005 | Accepted and implemented for Phase 2 | Runtime supervision is explicit, runtime-neutral, bounded, and fail-closed. | Required components fail fast only after declared recovery is exhausted; optional degradation, retry, restart, deadlines, queues, dead letters, and recovery ownership must appear in the graph. Defaults are 5 s readiness, 2 s drain, 2 s operation, retry/restart off, bounded fail-on-overflow queues, and no stateful restart without a recovery owner. |
| AD-006 | Accepted and implemented for Phase 3 | Delivery is at least once; message/operation identity, per-session ordering, optimistic revisions, and stale-result outcomes are governed. | Replays are expected and idempotent, identity/content conflicts are fatal, sequence gaps retry without advancing, late/stale inputs reject without failing the component, and user edits remain authoritative. |
| AD-007 | Accepted and implemented; extended in Phase 4C | All local AI work uses one durable, non-preemptive, concurrency-one execution lane. | Pending work is transcription, transcript correction/formatting, logged-item extraction, then classification enrichment; invocation order is FIFO within a workload, capacity failure is explicit, and restart recovery cannot silently duplicate completed model work. |
| AD-008 | Accepted for Phase 4 implementation | Raw audio is ephemeral after transcription; PCM16/16 kHz/mono is the deterministic fake format. | Argus needs transcript evidence, not an accidental recording archive. Any real retry buffer must be a separate bounded, permissioned, retention-governed capability. |
| AD-009 | Accepted for Phase 4 implementation | Partial hypotheses are visible read-only projections; confidence commits ordered words; finalized segments become editable revisioned state. | Word-by-word responsiveness is preserved without allowing unstable provider text into extraction or permanent history. Original STT evidence and provenance survive user edits. |
| AD-010 | Accepted process rule | Deferred packages, SDKs, providers, thresholds, storage, transport, and platform choices are tracked centrally with evidence triggers. | `PENDING-DECISIONS.md` prevents temporary POC defaults from silently becoming production commitments; Phase 4F accepts inline base64 NDJSON only for deterministic POC evidence and keeps production transport/chunk limits deferred. |
| AD-011 | Accepted and governed for Phase 4B | Committed STT words are immutable evidence; provider or contextual-language correction is a provenance-bearing proposal accepted only by the active transcript owner. | Similar-sounding alternatives and bounded surrounding context can improve wording without allowing AI or an STT provider to silently rewrite evidence. Every proposal identifies its exact word range, implementation, policy profile, and instruction version. |
| AD-012 | Accepted and governed for Phase 4B | Punctuation and capitalization remain provisional until segment finalization. | Argus may use provider-native formatting or an adjacent contextual formatter, while extraction/history consume only the active owner's finalized text. |
| AD-013 | Accepted and governed for Phase 4B | Active transcript state and permanent transcript history have separate explicit contracts and sole owners. | Finalized active segments use optimistic revisions and retain original STT/word provenance; permanent history is append-only and accepts entries only through an explicit idempotent append boundary. |
| AD-014 | Accepted and governed for Phase 4B | Logged-item generation receives an exact source range plus a versioned policy/instruction profile and explicit context bounds. | Lookback, forward context, and maximum context characters are visible contract parameters, making model behavior auditable without coupling the wire to one provider's raw prompt syntax. |
| AD-015 | Accepted and implemented for Phase 4C proof | The live transcript is one updating read-only provisional row that becomes an editable finalized segment. | Immediate feedback shows the system is working while correction, capitalization, grammar, and punctuation settle in place. Argus synthesizes stable word IDs when the provider does not supply usable identities. |
| AD-016 | Accepted and implemented for Phase 4C proof | Eligible corrections auto-apply before finalization under an explicit match and confidence policy. | The active owner verifies target ID and expected source text and preserves evidence. The fake threshold is 0.90; lower meaningful proposals become review flags rather than silent edits. |
| AD-017 | Accepted direction; contract evidence implemented | Highlight only unresolved ambiguity or meaningful correction review—not every low-confidence token or accepted correction. | Focused `review_flags` keep the transcript readable and carry stable word IDs/candidates for a later accessible UI treatment. Exact styling remains evidence-driven. |
| AD-018 | Accepted, implemented in memory, and replay-proven through Phase 4E | Append every authoritative finalized transcript revision. | Active state presents the latest revision; append-only history retains revision 0 and every accepted edit with original STT/correction provenance. Exact replay does not multiply the logical revision or history entry. Durable storage and bounded active-history retention remain Phase 6. |
| AD-019 | Accepted and implemented for scheduler proof | AI workload priority is transcription, transcript correction/formatting, logged-item extraction, then classification. | Correction cannot interrupt active transcription, extraction waits for finalized text, and classification remains lowest priority. The deterministic corrector consumes no model slot. |
| AD-020 | Accepted and implemented for Phase 4D proof | First-satisfied pause, size, deterministic topic, or maximum-latency signal closes a contiguous authoritative source window; every coincident reason remains visible. | Maximum latency is mandatory, primary precedence is stable, and production thresholds remain evidence-driven rather than hidden defaults. |
| AD-021 | Accepted and implemented for Phase 4D proof | Lookback and forward segments are bounded context, never duplicate authoritative source ownership. | Context can improve interpretation while stable source IDs/timestamps remain singular, contiguous, non-overlapping, and auditable. |
| AD-022 | Accepted and implemented for Phase 4D proof | Fake transcription enters the global highest-priority scheduler workload, and topic input is deterministic policy data rather than AI classification. | The graph proves concurrency-one admission and provider replacement without adding a model, STT SDK, or topic-classification package prematurely. |
| AD-023 | Accepted for Phase 5 | Model transport, logged-item ownership, and durability remain separate boundaries. | Phase 5A proves separate in-memory active/history owners with deterministic extraction. Phase 5B may use an environment-configured provider-neutral local HTTP adapter while retaining the fake. Model failures preserve context for retry and create no guessed item; optional classification cannot block primary extraction. Durable storage remains Phase 6. |
| AD-024 | Accepted for Phase 8 POC foundation | The browser UI and loopback Node bridge remain the POC host; host-specific permissions stay behind replaceable adapters/providers. | Phase 8 can establish default-deny declarations, supported Node enforcement, and inspectable packaging without selecting Electron/Tauri or pulling real microphone, STT, or model providers forward. Native and OCI execution remain unproven until evidence selects toolchains. |
| AD-025 | Accepted and implemented for Phase 8 | Component authority is declared per manifest, denied unless declared, and never simulated. | Nine authority classes are declarable; an omitted class, an omitted scope list, and an explicit `false` all mean none. Filesystem authority uses a host-neutral named scope rather than a host path, so a manifest cannot express traversal and a future container host can map the same scope onto a mount unchanged. A capability the installed host cannot enforce is refused at declaration time instead of being accepted and simulated, so microphone, component clipboard, model credentials, component listeners, and container-only resource limits are refused while `AUD-002`, `SEC-001`, and `CNT-001` stay open. |
| AD-026 | Superseded by AD-028 | Every enforcement claim states whether it is OS-enforced, adapter-enforced, or deferred. | Independent review found that this taxonomy mislabeled Node/V8 runtime controls as OS controls and described configuration restriction too broadly as outbound-network enforcement. The underlying denial behavior and documented socket gap remain valid. |
| AD-027 | Accepted and implemented for Phase 8 | A graph reduces to a deterministic inspectable package with per-file integrity hashes. | One artifact per graph records the graph, contract catalog and every schema/changelog, each manifest with fully expanded authority and declared files, the shared component libraries, and a package digest. Path escape, undeclared component files, secrets, and integrity drift are refused. A component can no longer ship code that no declaration accounts for. |
| AD-028 | Accepted; terminology correction pending | Enforcement claims distinguish Node-runtime-enforced, adapter/configuration-restricted, and deferred boundaries; OS-enforced is reserved for controls actually imposed below the runtime. | Node `--permission` and V8 heap limits are runtime controls. The current endpoint allowlist restricts approved model configuration but does not contain direct `node:net` sockets. Real socket containment requires a future provider under `CNT-001` or a Node runtime with a network permission control. |
| AD-029 | Accepted and implemented | The standalone product host is Electron with a narrow context-isolated preload and a supervised production graph. | Electron owns media permission requests, durable session-root selection, host clipboard/folder capabilities, shutdown, and the production graph. The renderer has no Node/filesystem/process access; the browser bridge remains the deterministic POC path. |
| AD-030 | Accepted and implemented; physical acceptance pending | Real capture uses Electron `getUserMedia` and an AudioWorklet resampler, while real transcription uses whisper.cpp `v1.9.1` and real logged-item extraction uses Ollama `llama3.2:3b` through the provider-neutral lane. | The desktop path has no fake fallback. Missing dependencies are visible capability failures. Setup records resolved paths/model checksum, and physical device/model measurements remain the next acceptance evidence. |
| AD-031 | Accepted and implemented; physical acceptance pending | A closed session is reviewed as sealed read-only history; its primary capture control becomes **New Session**, which creates a fresh identity through the trusted Electron/Node boundary and real lifecycle owner. | Close must not strand the application on a non-writable session or accidentally reopen persisted data. The production graph remains alive to accept the new recording lifecycle. |
| AD-032 | Accepted and implemented; threshold evidence pending | Real utterance finalization is driven by captured audio energy with a genuine-speech gate and bounded configurable pause threshold; the current default is 1,200 ms. | Timers may schedule work but cannot create transcript content or boundaries. Physical-device validation must measure the threshold against latency, false boundaries, and missed pauses. |

## Superseded directions retained for context

| Former direction | Replaced by | Why it changed |
| --- | --- | --- |
| Show task, note, observation, or idea as the primary identity of every extracted row. | PD-001 and PD-004 | It merged extraction with classification, overstated model certainty, and added visual weight. |
| Place toast notifications near the incoming list content. | PD-005 | A growing stack could obscure the live working area; the header has more suitable negative space. |
| Let the orchestrator implicitly own startup, failures, terminal results, or completion. | AD-001 and AD-002 | Hidden operational authority violated the architecture's explicit wiring and replaceability goals. |

## Visual hierarchy

The current layout intentionally reads in this order:

1. **Session identity and capture state** in the header.
2. **Raw evidence** in the left pane.
3. **Succinct logged meaning plus provenance** in the right pane.
4. **Persistence and export status** in the footer.
5. **Detailed session/storage information** in an on-demand drawer.
6. **Irreversible finalization** in a focused modal.

The dark, compact presentation is optimized for a long-running desktop companion: muted structural chrome, bright state/accent colors, monospaced timestamps, complete-row hover/selection/edit states, and motion limited by the user's reduced-motion preference.

## Decision update rule

When product testing changes a direction:

1. Add a new row with a new ID.
2. Mark the old row **Superseded** rather than deleting it.
3. State the evidence or user problem that caused the change.
4. Update the capability catalog and the live code-adjacent ADR when contracts or runtime behavior are affected.
5. Record the implementation and verification in the newest changelog entry.
