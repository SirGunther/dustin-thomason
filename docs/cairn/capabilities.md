# Cairn Capability Catalog

This catalog describes Cairn's UI as frozen in `Cairn-POC-v1-2026-08-20` and records the
Phase 0 architecture proofs beside it. It separates what actually works from what is
simulated, so a good-looking prototype is not mistaken for a working tool.

**The single most important line in this document:** nothing in Cairn writes to disk. Every
save target is browser storage or memory.

**The second most important line, as of Phase 7:** Cairn now requires a served origin.
`npm run serve`, then `http://127.0.0.1:8790/`. The page boots a component graph, and a
`file://` page cannot construct a Worker at all — so double-clicking `index.html` no longer runs
the app. **As of Phase 8 it must be that server specifically**: `npm run serve` is
`node tools/serve.mjs`, and it is what sends the Content Security Policy. Any other static server
yields no policy at all, and nothing in the page says so. Two behaviours changed with it: an unsaved edit does not survive a reload, and the
workspace is single-root. Both are consequences of document text having exactly one owner and
one component holding filesystem authority.

## Status legend

- **Working** — implemented and verified against a real check.
- **UI POC** — implemented in the browser, but the behavior is simulated, in-memory, or
  scoped to the embedded sample vault.
- **Specified** — documented or styled, but not connected end to end.
- **Deferred** — deliberately reserved for a later slice.

## Known limitations

- Nothing writes to disk, in any mode.
- **The app needs a served origin.** `file://` cannot construct a Worker, so `npm run serve`.
- **An unsaved edit does not survive a reload.** Text has exactly one owner and the page keeps
  no copy.
- **The workspace is single-root.** The additive multi-root workspace was not carried past
  Phase 7.
- **The security policy only exists when Cairn's own server is what served the page.** Any other
  static server, no policy, no warning.
- **`indexedDB` cannot be denied to a worker.** The graph records who may use it; nothing enforces
  that.
- **A route log cannot tell you what a message said**, only what caused what. That is deliberate
  and is the price of text having exactly one owner.
- **The route log is only as complete as the components' own reporting.** There cannot be an
  independent observer without giving the kernel a port it is not allowed to hold.
- **`innerHTML` is still an unguarded sink.** CSP does not govern it; `TT-001` tracks Trusted
  Types.
- **Remote images in notes do not load**, deliberately — they are a script-free exfiltration
  channel.
- A picked folder's _permission_ does not survive a reload; the root itself is remembered in
  IndexedDB and needs one gesture to re-grant.
- External edits made in another editor are invisible until a save is attempted against one.
- Only filenames are searchable, not content — and still matched linearly in the interface on
  every keystroke, which is what `SRC-001` exists to decide.
- Light mode works but was derived from a neighbouring project rather than designed; see `PAL-003`.
- Chromium only; Firefox has no directory picker.
