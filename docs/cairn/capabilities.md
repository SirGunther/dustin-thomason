# Cairn Capability Catalog

This catalog preserves the frozen `Cairn-POC-v1-2026-08-20` baseline and describes the live
architecture application beside it. It separates historical POC behavior from current governed
behavior so neither is mistaken for the other.

**The single most important line in this document:** the live application reads and mutates
picked folders. Exactly one component reads the filesystem and exactly one component writes it;
the interface holds neither authority.

**The second most important line, as of Phase 7:** Cairn now requires a served origin.
`npm run serve`, then `http://127.0.0.1:8790/`. The page boots a component graph, and a
`file://` page cannot construct a Worker at all — so double-clicking `index.html` no longer runs
the app. **As of Phase 8 it must be that server specifically**: `npm run serve` is
`node tools/serve.mjs`, and it is what sends the Content Security Policy. Any other static server
yields no policy at all, and nothing in the page says so. An unsaved edit does not survive a
reload, because document text has exactly one owner. Picked roots do persist, and the workspace
is multi-root; read and write handles remain divided between their declared filesystem owners.

## Status legend

- **Working** — implemented and verified against a real check.
- **UI POC** — implemented in the browser, but the behavior is simulated, in-memory, or
  scoped to the embedded sample vault.
- **Specified** — documented or styled, but not connected end to end.
- **Deferred** — deliberately reserved for a later slice.

## Document

The document region is now a reusable `@cairn/dantalion` package in the sibling
`PDProjects/Dantalion` repository. The host supplies an opaque document key and mount; the
package owns projection drawing, preview / split / source modes, the formatting ribbon, gutter,
and rich-editor lifecycle. It emits declared intents and never reads the filesystem or writes DOM
outside its mount. Cairn consumes the package through its local `file:../Dantalion` dependency and
`components/dom-owner/`; WorkLists consumption remains phase 2.

The surface and rich-editor interfaces are documented in Dantalion under
`components/document-surface/INTERFACE.md` and `components/rich-editor/INTERFACE.md`. The Q1
style probe passed under Dantalion's served CSP: constructed stylesheets apply, while the shipped
surface carries its own `surface.css` stylesheet link so the styles travel with the package.

## Known limitations

- **The app needs a served origin.** `file://` cannot construct a Worker, so `npm run serve`.
- **An unsaved edit does not survive a reload.** Text has exactly one owner and the page keeps
  no copy.
- **The workspace is multi-root but Chromium-only.** Directory handles depend on the File System
  Access API.
- **The security policy only exists when Cairn's own server is what served the page.** Any other
  static server, no policy, no warning.
- **`indexedDB` cannot be denied to a worker.** The graph records who may use it; nothing enforces
  that.
- **A route log cannot tell you what a message said**, only what caused what. That is deliberate
  and is the price of text having exactly one owner.
- **The route log is only as complete as the components' own reporting.** There cannot be an
  independent observer without giving the kernel a port it is not allowed to hold.
- **`innerHTML` is still an unguarded sink.** CSP does not govern it; `TT-001` tracks Trusted
  Types.
- **Remote images in notes do not load**, deliberately — they are a script-free exfiltration
  channel.
- A picked folder's _permission_ does not survive a reload; the root itself is remembered in
  IndexedDB and needs one gesture to re-grant.
- External edits do not appear automatically. Refresh Explorer re-enumerates them; an attempted
  save against a changed file is refused.
- Only filenames are searchable, not content — and still matched linearly in the interface on
  every keystroke, which is what `SRC-001` exists to decide.
- Light mode works but was derived from a neighbouring project rather than designed; see `PAL-003`.
- Chromium only; Firefox has no directory picker.
- No screen-reader pass. Roles and labels are present, but the tree uses a
  single-tabstop-plus-arrow model rather than a full ARIA treegrid.
- No visual regression testing of any kind. A stylesheet change that kept the geometry and
  ruined the look would pass every gate. With the checkbox splice and split-pane geometry now
  guarded by the Cairn shell suite and the standalone Dantalion harness, this remains a separate
  coverage gap rather than part of `TST-001`.
