## Terms

| Term | Means |
| --- | --- |
| AJSF | The job submission form. Its proceeding-creation endpoint is `POST /proceedings` on `ProceedingJobSubmissionController` (`pjs/application/controllers/actions/create-job-submission-proceedings-action/create-job-submission-proceedings.action.ts:15-24`), which calls `JobSubmissionService.createProceedings`. |
| File Navigator | The other proceeding-creation endpoint, `ProceedingService.createProceedings`. Covered by INT-140, not by this ticket. |
| europa-back-end | The audit service repo. It stores audit records received over SQS and serves `/audit-events/search-paginated`, which builds the display `path` string. |
| Europa audit page | The page inside `atlas-front-end` (`src/europa/`). It holds the Event Type and Resource Type dropdowns (`atlas/utils/constants.ts`) and renders the `path` string it receives. |
| Proceeding path | `<MMYYYY>/<jobId>/<proceedingId>`: the job date's month and year, the job id and the proceeding id. The ticket's "date/job ID/proceeding ID" (INT-141.md:17-19). It contains only digits and `/`. |

## Scope assessment

INT-141 adds one event to an existing chain. There is no migration, API change or europa-back-end schema change (LD-010).

### Already provided

- **Callisto:** the `CREATED` event type and `PROCEEDING` resource type (E1, E2); the proceeding audit aggregator, dispatcher, assembler and converter (E3); the job-date read and month-year function (E7).
- **europa-back-end:** storage of any state fields (E8); the Resource Type filter (E4); `toDisplayValue` on `INT-138` (E12).
- **atlas-front-end:** `CREATED` in the Event Type list with its colour (E2); the path splitter and multi-line template on `INT-138` (E12, E13).

### Changes INT-141 adds

**callisto-back-end**

1. `ProceedingAuditAggregator`: add `dispatchProceedingAuditCreatedEvent(params)`, which calls the dispatcher with `eventType: AUDIT_EVENT_TYPE.CREATED`.
2. `ProceedingAuditParams.proceeding`: add optional `path`. The assembler passes it to the converter.
3. `ProceedingToAuditEventResourceConverter`: when `path` is given, `resourcePath` = path, `resourceBucket` = `''`, and both states are `{ path, value }` (LD-005). Otherwise the output is unchanged (LD-006).
4. `pjs/domain/ports/job-submission-proceeding-audit.port.ts`, bound in `ProceedingsModule` with `useExisting: ProceedingAuditAggregator` and exported (LD-008).
5. `pjs/domain/projections/job-submission-proceeding-created-audit.projection.ts` and `JobSubmissionProceedingAuditAssembler` (LD-015), registered in the module.
6. `JobSubmissionService.createProceedings`: read the job date, create the proceedings, assemble one audit record per proceeding, dispatch each one; catch and log any assembler error or dispatch rejection, and return the created proceedings (LD-002, LD-003, LD-004, LD-012).

**europa-back-end**

- The `CREATED` + `PROCEEDING` branch in the paginated search TS (LD-009), with specs.

**atlas-front-end**

- `'PROCEEDING'` in `resourceTypes`; the optional maximum segment count on `toPathSegments`; the two-segment split for `CREATED` + `PROCEEDING` rows (LD-007), with specs.
