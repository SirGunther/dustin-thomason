## Rejected paths, recorded so they are not retried

Beyond the per-row rejections above, these were considered and dropped with reasons (full table in report §6):

- **Injecting the port into `RenameProceedingFileTS`** — module cycle; no `AuthUser` at that layer; fires for all three surfaces.
- **A new `RenameDeliverableFileTS` delegating to the aggregator** — fails `transaction-scripts-no-aggregators` at `severity: 'error'`. This is the one a reasonable implementer reaches for first.
- **A new `RenameDeliverableFileTS` re-implementing the rename** — forks extension preservation, lineage and duplicate-name validation into a second writer of `files.file_name`. Also out of class: it changes rename behaviour.
- **Emitting from `ProceedingFileAuditAggregator`** — same cycle, shared with surface B, runs after commit.
- **A projection-driven runner over `files.updated_at`** — design Q5 calls it an antipattern for this epic.
- **`ON CONFLICT DO NOTHING` on the outbox insert** — **worse**: preserves the first, stale payload where `save()` preserves the later, correct one.
- **A feature flag** — the module does not gate its outbox writes and the shipped sibling is unflagged; flagging one of seven events is worse than flagging none.
- **Folding a monotonic discriminator into `DeterministicEventIdHelper`** to fix the collision airtight — changes id derivation shared with the shipped `file.created.v1` and the `proceedings-command` runner.
